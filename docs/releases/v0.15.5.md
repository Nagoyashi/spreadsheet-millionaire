# v0.15.5 — Tracker history control: snapshot editing + recurring overview (2026-07-26)

Two owner-requested tracker gaps (#317, #318), both about controlling data
you've already entered rather than only adding more.

## Net Worth — edit and delete past snapshots (#318)

Snapshots were append-only: a snapshot taken right after an accidental item
deletion left a permanently wrong point in the Net Worth Over Time trend
(the motivating incident: a deleted real-estate item made the chart show a
−200k dip forever).

- `PUT`/`DELETE /api/net-worth/snapshots/<id>` — user-scoped (hard rule #6),
  CSRF-protected, rate-limited like every other `nw_*` write. Totals ARE
  editable on update (unlike create, which computes them from the live
  summary); `net_worth` is always recomputed server-side from the totals and
  is rejected as an input field, so it can never drift from them.
- **SnapshotManager** — a "Manage snapshots" list under the trend chart:
  inline edit of date/assets/liabilities, two-step in-app delete confirm
  (no `window.confirm` — #284).

## Income & Expenses — the Recurring overview (#317)

Recurring transactions could be created but not managed: nothing showed all
active rules together, and stopping one meant knowing to edit the row and
flip Repeat back to "Does not repeat".

- **RecurringPanel** on the Overview tab: every active rule at a glance —
  amount/type, category, cadence, and the next occurrence (new
  `nextOccurrence()` in `recurrence.js`, month-end-clamp semantics
  consistent with the existing projections: a Jan-31 monthly rule shows
  Feb-28, never skips to March).
- **Stop** (two-step confirm): resets the rule to a one-off — the anchor row
  stays as real history; only future projections stop.
- **Edit** hands the transaction to the Transactions tab, which opens its
  existing edit form pre-filled.
- Edits propagate to the Overview, monthly grid, and forecast by design —
  occurrences are derived at read time from the single row; there is no
  second copy to go stale.
